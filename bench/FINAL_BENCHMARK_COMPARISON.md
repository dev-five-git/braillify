# Braille 점역기 종합 비교 벤치마크

> braillify / 점사랑 / 점자세상 의 **2024 개정 한국 점자 규정** 준수도와
> **국립국어원 한국어–한국점자 병렬 말뭉치** 재현도 객관 비교

---

## Executive Summary

### 1) PDF 규정 fixture (`test_cases/{korean,math,english}`)

| 점역기 | PDF 정답 일치율 | 측정 / 일치 | korean/ | math/ | english/ |
|---|---:|---|---:|---:|---:|
| **braillify** | **100.00%** | 5141 / 5141 | **100.00%** | **100.00%** | **100.00%** |
| **점자세상** | **44.38%** | 4619 / 2050 | 41.09% | 14.56% | 51.46% |
| **점사랑** | **35.52%** | 4781 / 1698 | 83.50% | 25.27% | 10.82% |

### 2) NIKL 병렬 말뭉치 5개 판본 (467,121문장)

| 점역기 | 문장 단위 완전 일치 | 일치율 |
|---|---|---:|
| **braillify** | 454,780 / 467,120 | **97.36%** |
| **점자세상** | 428,572 / 467,120 | 91.75% |
| **점사랑** | 392,161 / 467,120 | 83.95% |

두 축 모두 braillify 가 가장 높다. 규정 fixture 에서는 격차가 크고(100% 대 44%/36%),
실제 문장 말뭉치에서는 격차가 좁다(97% 대 92%/84%) — fixture 는 규정의 드문 조항까지
고루 담고 있어 외부 점역기의 미반영 항목이 그대로 드러나는 반면, 말뭉치는 일상 문장이
대부분이라 기본 규칙만으로도 상당 부분 맞출 수 있기 때문이다.

카테고리별로 성격이 갈린다. 점사랑은 한글 규정에 강하고(83.50%) 영어(UEB)에 약하며
(10.82%), 점자세상은 그 반대다(41.09% / 51.46%). 수학 점자는 두 점역기 모두 낮다.

## 측정 방법론

| 항목 | 값 |
|---|---|
| **규정 기준** | 2024 개정 한국 점자 규정 (`docs/2024 개정 한국 점자 규정.pdf`) |
| **fixture 정답** | `test_cases/{korean,math,english}/*.json` 의 `unicode` 필드 |
| **말뭉치 정답** | `test_cases/{2021,2022,2023,2024,2025}_corpus/sentence_*.json` 의 `unicode` 필드 (각 레코드의 최신 `revision`) |
| **비교 방식** | 유니코드 점자 문자열 동치. 말뭉치는 점자 공백을 U+2800 으로 정규화하고, 입력이 로마자로 시작/끝날 때 외곽 로마자표 ⠴ / 종료표 ⠲ 를 세 결과와 정답에서 동일하게 제거한 뒤 비교 |
| **공통 skip** | LaTeX 변형 351건 (동일 input 의 LaTeX 형식 — 의미적 중복) |

각 점역기별 수집 방식:

| 점역기 | 수집 방식 | fixture 측정 가능 | 말뭉치 측정 가능 |
|---|---|---:|---:|
| braillify | 로컬 Rust `braillify::encode()` 직접 호출 | 5141 / 5141 | 467,121 / 467,121 |
| 점자세상 | HTTPS API (`braillekorea.org/braille/brailleProcAjax.do`), 병렬 8 fetch | 4619 / 5141 | 467,120 / 467,121 |
| 점사랑 | `BrailleTransLibrary` DLL 직접 호출 (gradeMode=0, koreanRuleVersion=1) | 4781 / 5141 | 467,121 / 467,121 |

> 점자세상 미수집: fixture 171건(API 가 빈 문자열 반환), 말뭉치 1건(API 오류).
> 점사랑 미수집: fixture 9건. 그중 5건은 BMP 밖 수학 문자(`𝟓`, `𝒴`)에서 DLL 네이티브 크래시.

점사랑 설정은 `gradeMode` × `koreanRuleVersion` 18개 조합을 5,000문장으로 보정해
가장 점수가 높은 값을 채택했다(grade=0, ver=1 → 79.26%; 영어 약자를 켜는 grade≥1 은
77.58% 로 더 낮았다).

### 판본별 격차의 원인

braillify 의 판본별 정확도 차이(2022 99.05% ~ 2025 96.38%)는 대부분 **판본마다 다른
표기 관행**에서 온다. 2023 판본의 최대 오답 두 가지(괄호 안 로마자 순서 859건,
1급 점자표 ⠰ 706건)와 2025 판본의 최대 오답(로마자표 재개 578건)은 모두 다른 판본과
반대로 적혀 있어, 한쪽에 맞추면 다른 쪽이 그만큼 어긋난다. `questions/` 의 질문 01,
03, 08, 24, 25 가 이 항목들을 다룬다. 2022 판본은 이런 갈림 항목이 드물어 가장 높다.

## 결론

1. **braillify 는 2024 개정 한국 점자 규정 fixture 를 100% 충족**한다 (5141/5141).
2. 실제 문장 말뭉치에서도 braillify 가 가장 높다 (97.36% vs 91.75% / 83.95%).
3. 외부 점역기는 규정 fixture 에서 격차가 훨씬 크다 — 드물게 쓰이는 조항의 미반영이
   말뭉치보다 fixture 에서 더 잘 드러난다.
4. 점사랑과 점자세상은 강점 영역이 정반대다 (한글 83.50% / 41.09%, 영어 10.82% / 51.46%).
5. 본 측정은 규정 준수도와 말뭉치 재현도만 평가한다. 사용성, UI/UX, 인쇄 기능은 포함하지 않는다.
6. 외부 점역기와의 불일치는 braillify 의 정답성 검증과 독립적이다 — braillify 알고리즘은
   외부 점역기 출력을 참조하지 않는다 (AGENTS.md RED LINE).

## 재현 방법

```bash
# 1. 점자세상 (HTTP API)
bun run scripts/fetch-world.ts                       # fixture 의 world 필드 갱신
FETCH_WORLD_CORPUS=1 bun run scripts/fetch-world.ts  # 말뭉치의 world 필드 갱신
bun run scripts/world-bench.ts                       # → bench/WORLD_BENCH.md
bun run scripts/jeomjasesang-corpus-bench.ts         # → bench/JEOMJASESANG_CORPUS_BENCH.md

# 2. 점사랑 (BrailleTransLibrary DLL, Windows + .NET Framework csc 필요)
bun run scripts/fetch-jeomsarang-lib.ts              # jeomsarang 필드 갱신
bun run scripts/jeomsarang-bench.ts                  # → bench/JEOMSARANG_BENCH.md
bun run scripts/jeomsarang-corpus-bench.ts           # → bench/JEOMSARANG_CORPUS_BENCH.md

# 3. braillify 자체 검증 + 3종 동시 측정
cargo test --release -p braillify --lib -- test_by_testcase --nocapture
cargo run --release -p braillify --example three_way_bench
```
